# itqan reciter catalog

An offline, dependency-free Python 3.11+ pipeline for preserving provider reciter snapshots, manually curating canonical reciter records, and deterministically generating a catalog. It does not implement a public SDK, discovery API, resolver, playback, caching, or frontend state.

## Ownership and layout

```text
data/raw/<provider>/        replaceable provider snapshots; generated by fetch-reciters
data/curated/reciters/      manually maintained canonical reciter Markdown; source of truth
data/curated/catalog.json   deterministic generated output from curated Markdown
templates/_template.md      starting point for a new curated reciter
docs/CURATION.md            curation format and rules
docs/CATALOG_ARCHITECTURE.md ownership, generated schema, and migration boundaries
src/reciter_fetcher/        fetch, audit, bootstrap, and catalog generator CLIs
tests/                      unittest suite
```

Never hand-edit `data/raw/` or `data/curated/catalog.json`. When they disagree, curated Markdown wins: correct the Markdown deliberately, then regenerate the catalog. `data/raw/` is upstream-shaped evidence; curated Markdown is the reviewed canonical mapping layer.

## Providers

| Curated tag | Provider domain | Raw file | Generated provider key |
|---|---|---|---|
| QFS | Quran Foundation surah/chapter reciters | `data/raw/quran_foundation/chapter-reciters.json` | `quranFoundationSurah` |
| QFA | Quran Foundation ayah recitations | `data/raw/quran_foundation/ayah-recitations.json` | `quranFoundationAyah` |
| MP3 | mp3quran.net | `data/raw/mp3quran/reciters.json` | `mp3Quran` |
| EA | everyayah.com | `data/raw/everyayah/recitations.json` | `everyAyah` |

QFS and QFA are separate provider domains and separate ID spaces, even when their numeric IDs coincide. Quran Foundation credentials are supplied as `QF_CLIENT_ID` and `QF_CLIENT_SECRET` in `.env` when refreshing its sources.

## Install

From the repository root:

```bash
pip install -e .
```

This installs `fetch-reciters`, `audit-reciters`, `bootstrap-catalog`, and `generate-catalog`.

## Normal workflow

```bash
fetch-reciters
audit-reciters --strict
generate-catalog
generate-catalog --check
```

1. `fetch-reciters` refreshes provider snapshots atomically for successful providers.
2. `audit-reciters --strict` verifies coverage and that every raw snippet still matches its curated copy, except documented curated-only metadata.
3. `generate-catalog` validates curated Markdown and atomically writes `data/curated/catalog.json`.
4. `generate-catalog --check` validates and confirms that the checked-in catalog is exactly the current deterministic output. It writes nothing.

If audit or generation reports an issue, resolve it explicitly in the affected curated Markdown; do not invent an identity, Arabic name, riwayah, style, capability, or representation merely to make the command pass. Literal `unknown` is valid only when it is an intentional, reviewed curated value.

## Running from a source checkout

```bash
PYTHONPATH=src python3 -m reciter_fetcher.cli
PYTHONPATH=src python3 -m reciter_fetcher.audit_cli --root . --strict
PYTHONPATH=src python3 -m reciter_fetcher.catalog_cli --root .
PYTHONPATH=src python3 -m reciter_fetcher.catalog_cli --root . --check
```

The separate `bootstrap-catalog --json` command is only for a reviewed, one-time migration from the legacy `styles -> riwayat` catalog. It is report-first, rejects the generated `riwayat -> styles` schema, and is not part of normal operation.

Run the full test suite with:

```bash
python3 -m unittest discover -s tests
```

## Adding a provider

Follow the complete provider checklist in `docs/CURATION.md`. Keep runtime dependencies empty.

For the curated file format, allowed curated-only fields, and post-refresh procedure, read [docs/CURATION.md](docs/CURATION.md). For the generated hierarchy and scope boundaries, read [docs/CATALOG_ARCHITECTURE.md](docs/CATALOG_ARCHITECTURE.md).
